FILETIME・LDAP タイムスタンプ変換の使い方

18 桁の数値の読み方・特別な値・よくある質問・根拠

English

▶ FILETIME・LDAP タイムスタンプ変換を使う

使い方

  1. 数値 → 日時: 18 桁の数を入れると、UTC・この端末の時刻・選んだタイムゾーンで表示します。pwdLastSet : 134347122000000000 のように行ごと貼れば、属性名から意味（0 や無期限など）も出します。
  2. 日時 → 数値: 日時を選ぶと、FILETIME（10 進・16 進）、Unix 秒、.NET の Ticks、一般化時刻と、LDAP フィルターの例を出します。
  3. まとめて変換: Get-ADUser ユーザー名 -Properties * の出力や、ldifde・csvde のファイルの中身を貼って「変換する」。日時の属性だけを拾って表にします。「表をコピー（TSV）」で Excel に貼れます。
  4. 結果の「この値を開くリンクをコピー」で、同じ値を開くリンクを作れます（値はリンクの # 以降に入り、サーバーには送られません）。

よくある質問

pwdLastSet や lastLogonTimestamp の 18 桁の数値は何ですか？
Windows の FILETIME で、1601 年 1 月 1 日 0 時（UTC）からの経過時間を 100 ナノ秒単位で数えた数です。1 秒は 10,000,000。PowerShell なら [datetime]::FromFileTimeUtc(値)、コマンドプロンプトなら w32tm /ntte 値 で日時に直せます（Microsoft Learn）。
lastLogonTimestamp が実際の最終ログオンと合わないのはなぜですか？
lastLogonTimestamp は、ログオンのたびではなく、前の値が「今 − msDS-LogonTimeSyncInterval（既定 14 日）」より古いときだけ書き換わります。そのため既定では 9〜14 日ほど遅れることがあります（Last-Logon-Timestamp、KB 2679653）。休眠アカウントの洗い出し用の値で、正確な最終ログオンが必要なら全 DC の lastLogon の最大を見ます。
lastLogon と lastLogonTimestamp の違いは？
lastLogon はログオンのたびに更新されますが、その DC にだけ記録され複製されません（Last-Logon）。lastLogonTimestamp は全 DC に複製されますが、更新が最大 14 日ほど遅れます。
accountExpires が 9223372036854775807 や 0 なのはどういう意味ですか？
どちらも「無期限」です。9223372036854775807（0x7FFFFFFFFFFFFFFF）はアカウント作成時の既定値で、一度期限を設定してから「無期限」に戻すと 0 になります（Account-Expires）。LDAP で期限切れのアカウントを探すときは、0 と 9223372036854775807 を除きます。
ADUC の「アカウントの期限」と accountExpires が 1 日ずれるのはなぜですか？
ADUC は「その日の終わり」で期限を表示します。accountExpires に入っているのは期限切れになる瞬間（翌日の 0 時）なので、ADUC の表示は accountExpires の日付より 1 日前になります（Account Expiration）。
pwdLastSet が 0 のときは？
「次回ログオン時にパスワードの変更が必要」です（「パスワードを無期限にする」が設定されていない場合。Pwd-Last-Set）。
maxPwdAge や lockoutDuration がマイナスの値なのはなぜですか？
日時ではなく期間で、100 ナノ秒単位の負の数で持つ決まりです（Lockout-Duration、[MS-SAMR] の delta time）。例えば -36288000000000 は 42 日、-18000000000 は 30 分です。パスワードの期限は pwdLastSet に maxPwdAge の絶対値を足した日時です。
パスワードの有効期限を直接知る方法は？
msDS-UserPasswordExpiryTimeComputed を読みます（Get-ADUser ユーザー名 -Properties msDS-UserPasswordExpiryTimeComputed）。細かいパスワードポリシー（PSO）も反映された値です。9223372036854775807 なら期限切れにならず、0 なら pwdLastSet が 0 です（[MS-ADTS] 3.1.1.4.5.33）。
変換した時刻が 9 時間ずれるのはなぜですか？
FILETIME は UTC（協定世界時）で入っています。日本時間は UTC より 9 時間進んでいるので、日本時間で見るときは 9 時間足します。このツールは UTC・この端末の時刻・選んだタイムゾーンを並べて表示します。
Excel で変換するには？
値が A1 にあるとき、=A1/864000000000-109205 で UTC の日時（シリアル値）になります。日本時間なら =A1/864000000000-109205+9/24。セルの表示形式を日付と時刻にしてください。Excel の数値は 15 桁までなので、1 秒未満は正確ではありません。
入力した値はどこかに送信されますか？
送信しません。計算はすべてお使いのブラウザの中で行います。保存するのは「表示するタイムゾーン」の選択だけです。

根拠と確認日

変換の式（1601-01-01 UTC から 100 ナノ秒単位）は変わりません。属性ごとの意味と既定値は、次の Microsoft の文書で確かめました。

  • File Times（FILETIME の定義）
  • Pwd-Last-Set・User Security Attributes（pwdLastSet の 0 と -1）
  • Account-Expires・Account Expiration (LDAP Provider)（無期限の値、ADUC の 1 日前表示）
  • Last-Logon-Timestamp・KB 2679653・Last-Logon・Lockout-Time
  • Lockout-Duration・[MS-SAMR] 1.1 Glossary（delta time）（負の期間）
  • [MS-ADTS] 3.1.1.4.5.33 msDS-UserPasswordExpiryTimeComputed
  • Policy CSP - DeviceLock: MaximumPasswordAge（既定 42 日）
  • String(Generalized-Time) syntax（whenCreated の形）
  • KB 555936（w32tm /ntte。例の値 128271382742968750 をテストで確かめています）
  • DateTime.Ticks（.NET の Ticks）

ご利用上の注意・データの扱い

  • 送信しないもの：入力した値・貼り付けた一覧は、お使いのブラウザの中だけで計算します。どこにも送信せず、保存もしません。
  • 保存されるデータ：「表示するタイムゾーン」の選択だけを、このブラウザに保存します（filetime_tz）。
  • 共有リンク：「この値を開くリンクをコピー」で作るリンクには、値と属性名が URL の「#」以降に入ります。「#」以降はサーバーに送られませんが、リンクを渡した相手には値が見えます。
  • 結果の扱い：変換は定義どおりの計算ですが、属性の意味の説明は Microsoft の文書に拠る一般的なものです。運用の判断はお使いの環境で確かめてください。PowerShell の例は文字として表示するだけで、このページが実行することはありません。
