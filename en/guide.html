How to use it

  1. Timestamp → date: enter an 18-digit value to see it in UTC, in this device's time zone and in a time zone you pick. Paste the whole line, such as pwdLastSet : 134347122000000000, and the attribute name is used to explain special values.
  2. Date → timestamp: pick a date and time to get the FILETIME (decimal and hex), Unix time, .NET ticks, generalized time and ready-made LDAP filter examples.
  3. Bulk convert: paste the output of Get-ADUser name -Properties * or an ldifde / csvde export and press Convert. Only timestamp attributes are picked up; "Copy table (TSV)" pastes straight into Excel.
  4. "Copy a link to this value" makes a link that reopens the same value. The value is after the #, so it is never sent to a server.

Frequently asked questions

What is the 18-digit number in pwdLastSet or lastLogonTimestamp?
It is a Windows FILETIME: the number of 100-nanosecond intervals since 1601-01-01 00:00 UTC, so one second is 10,000,000. In PowerShell use [datetime]::FromFileTimeUtc(value); at a command prompt use w32tm /ntte value (Microsoft Learn).
Why doesn't lastLogonTimestamp match the user's real last logon?
It is not updated at every logon. A DC only writes a new value when the stored one is older than now minus msDS-LogonTimeSyncInterval (14 days by default), so by default it can be 9 to 14 days behind (Last-Logon-Timestamp, KB 2679653). It is meant for finding stale accounts. For the exact last logon, take the newest lastLogon across all domain controllers.
What is the difference between lastLogon and lastLogonTimestamp?
lastLogon is updated at every logon but only on the DC that handled it and is not replicated (Last-Logon). lastLogonTimestamp is replicated to every DC but can lag by up to about 14 days.
What does accountExpires = 9223372036854775807 or 0 mean?
Both mean the account never expires. 9223372036854775807 (0x7FFFFFFFFFFFFFFF) is the default for a new account; an account that had an end date and was set back to Never gets 0 (Account-Expires). When you search for expired accounts with LDAP, exclude both values.
Why does Active Directory Users and Computers show the account expiry one day earlier than accountExpires?
ADUC shows the expiry as the end of a day. accountExpires stores the moment the account expires, which is midnight at the start of the following day, so ADUC displays the date one day earlier than the date in accountExpires (Account Expiration).
What does pwdLastSet = 0 mean?
User must change password at next logon, unless the account has Password never expires set (Pwd-Last-Set).
Why are maxPwdAge and lockoutDuration negative?
They are intervals, not dates, and are stored as a negative number of 100-nanosecond units (Lockout-Duration; "delta time" in the [MS-SAMR] glossary). -36288000000000 is 42 days and -18000000000 is 30 minutes. A password expires at pwdLastSet plus the absolute value of maxPwdAge.
How do I get a user's password expiration date directly?
Read msDS-UserPasswordExpiryTimeComputed (Get-ADUser name -Properties msDS-UserPasswordExpiryTimeComputed). It already takes fine-grained password policies into account. 9223372036854775807 means the password never expires; 0 means pwdLastSet is 0 ([MS-ADTS] 3.1.1.4.5.33).
How do I convert a FILETIME in Excel?
With the value in A1, =A1/864000000000-109205 gives the UTC date and time as an Excel serial number; add your UTC offset in hours divided by 24 for local time (for example -5/24 for US Eastern standard time) and format the cell as date and time. Excel keeps 15 significant digits, so sub-second precision is lost.
Is anything I enter sent to a server?
No. All conversion happens in your browser. The only thing stored is your time zone choice.
